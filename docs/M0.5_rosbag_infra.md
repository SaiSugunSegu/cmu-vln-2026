# M0.5 — Rosbag Infra (offline replay)

Replay a recorded bag **instead of the live Unity simulator**, so `smart_vlm` runs offline — no
Unity, no GPU. The bag holds the challenge inputs (`/camera/image`, `/registered_scan`,
`/sensor_scan`, `/terrain_map`, `/terrain_map_ext`, `/state_estimation`) + `/tf`, `/tf_static`.

## Where bags live

- Host: `<repo>/data/bags/<scene>/` (one folder per scene = `metadata.yaml` + `*.mcap`), gitignored.
- Container: bind-mounted at `/data/bags` (the `odyssey` service in `compose_gpu.yml`).

> **Moved:** bags used to live at `<repo>/bags/`. Host `data/` now maps 1:1 onto the
> container's `/data`, so there is a single mount and host `data/x` is always
> container `/data/x`. **The container path `/data/bags` did not change** — only the
> host location did. If you have scenes from before the move, relocate them once;
> they do not need re-downloading:
>
> ```bash
> mkdir -p data/bags && mv bags/* data/bags/ && rmdir bags
> ```
- Bags are **not** in git — each scene is a zip on [Google Drive](https://drive.google.com/drive/u/1/folders/13Br6vsKXcSDZwd-xLAY-LzEvPIUofKs7),
  listed in [`../data/bags/scenes.yaml`](../data/bags/scenes.yaml).

## Play

The launch **auto-downloads the scene if it's missing** (via `smart_vlm bag_fetch`), then plays it.
Run inside the ai_module container:

```bash
ros2 launch smart_vlm bag_replay.launch scene:=scene_0            # bag only
ros2 launch smart_vlm bag_replay.launch scene:=scene_0 args:=""   # single pass (default is --loop)
ros2 launch smart_vlm eval_bag.launch bag:=scene_0                # smart_vlm + bag (one command)
```

`eval_bag.launch` sets `wait_for_armed:=true` on the replay, so the bag holds at
`/pipeline/armed` — it starts only once a question has been asked and SAM has that question's
prompts, instead of streaming past a detector that is still loading weights. Standalone
`bag_replay.launch` (and `just bag-play`) leave the gate off and play immediately.

Downloading is one-time per host — bags land in the mounted `/data/bags` (= host `<repo>/data/bags/`)
and persist across container restarts. `gdown`/`pyyaml` ship in the ai_module image, so nothing to
install; the scene just needs a real `drive_id` in `data/bags/scenes.yaml`.

Playback keys: **SPACE** pause/resume · **→** step · **↑/↓** rate ±10%.

## Record + publish a new scene

```bash
# inside the ai_module container — record into the mounted /data/bags so it persists on the host
ros2 bag record /camera/image /registered_scan /sensor_scan \
  /terrain_map /terrain_map_ext /state_estimation /tf /tf_static -o /data/bags/<scene>
# then on the host:
cd <repo>/data/bags && zip -r <scene>.zip <scene> && sha256sum <scene>.zip
```

Upload the zip to the Drive folder → **Share → "Anyone with the link"** → copy the link; the
`<FILE_ID>` in `.../file/d/<FILE_ID>/view` is the `drive_id`. Add it to `data/bags/scenes.yaml`:

```yaml
  <scene>:
    drive_id: "<FILE_ID>"
    sha256:   "<hash>"   # optional
```

Commit `data/bags/scenes.yaml` only (never the zip/bag).

## Caveat

`--loop` replays tf with backward-jumping timestamps (transient tf-extrapolation warnings); use
`args:=""` for a single pass.
